## Task Board Usage

**Make sure to always be assigned to something!** If you’re assigned to the same thing for more than a day, either the task is too big (use subtasks) or you should ask for help.

### Task Guide

- **Epics**: collection of stories that serve a bigger picture; can take anywhere from a few weeks to a few sprints

- **Stories**: feature request from the user’s perspective. May take from a day to a week, roughly.

- **Subtasks**: part of a story, should take anywhere from an hour to half a day. Once every subtask is finished, the story should be finished.

- **Task**: separate from anything else and not directly for the end product; use for stuff like documentation, creating a presentation, that sort of thing.

### Kandan Board Guide

- **To Do**: list of tasks that need to be finished this sprint

- **In Progress**: What you’re currently working on. *One story at a time!!*

- **In Review**: When you’re done, let someone else on the team know so more than one person knows what’s changing and why. This doesn’t have to be a super detailed code review, just walk through the implementation and why you did the things you did.

- **Done**: Put stuff here when it’s reviewed, tested and otherwise completely finished.

## Git Guidelines

**main**: only push when a feature is fully finished on staging or on a feature branch. This means it’s tested and reviewed and passes all checks. ***Never individual/untested commits!!!!!!*** Our CI/CD should run here.

**staging**: push new work here when you want to test it in the bigger picture. Never individual commits. We can run CI tests here, but not CD.

**feature-name**: use for any work that’s in progress. Commit as often as reasonably makes sense, prefer not one huge commit at the end.
